# Как работать с проектом

## Запуск

```bash
python scripts/dev_server.py 5720        # http://localhost:5720/
```

- Только http: `file://` не годится (ES-модули, `fetch` JSON).
- Сервер многопоточный и отдаёт `Cache-Control: no-store` (раньше браузер держал
  старые JS/CSS). Если страница «висит» на загрузке модулей — перезапустить сервер.
- В среде Claude Code сервер поднимается инструментом превью по
  `.claude/launch.json` (конфигурация `geo-puzzle`), не через Bash.
- Окружение автора: Windows 10, Git Bash / MSYS2 (UCRT64) и PowerShell, Python 3,
  Node 22. В Git Bash пути вида `/c/Users/…`, а у `node.exe` — `C:/Users/…`.

## Как проверять изменения

Автотестов нет — проверка ручная и обязательная.

1. `node --check <файл.js>` для каждого изменённого JS (ловит синтаксис, не логику).
2. Запустить игру, пройти изменённое: уровень → режим → «Играть» → сама фича;
   смотреть консоль. Хороший приём — повесить `window.addEventListener('error', …)`
   до действий и прочитать массив ошибок (консоль вкладки хранит старые ошибки).
3. **Скриншот обязателен** для UI/видимости: свойства DOM могут выглядеть верно,
   а картинка — нет (и наоборот).
4. **Hover-интерфейсы** (флайауты, подсказки) — только настоящим движением мыши по
   пути, включая зазор между кнопкой и панелью; синтетические `mouseenter` не
   воспроизводят баги hit-testing.
5. Данные — проверять скриптом: `node --input-type=module -e "import { levels } from './levels/index.js'; …"`
   (число объектов, форма полей, соседние объекты на разумном расстоянии).
6. Ограничения Browser-панели Claude: анимации не идут без отрисовки, после
   `resize_window` на загруженной вкладке картинка ломается, на «чужом» размере
   окна скриншот мелкий — тогда открыть свежую вкладку, а числовые проверки делать
   через `getBoundingClientRect()`/`getComputedStyle()`. Не гнаться в ней за FPS и
   плавностью — это проверяет владелец.
7. Изменил скрипт сборки → перегенерируй данные и проверь `git diff --stat`: должен
   поменяться только ожидаемый файл.

## Планирование и порядок работы

| Размер задачи | Как вести |
|---|---|
| Мелкая правка, баг, добавление данных (город, место, аэропорт) | сразу в код; если сказано «без openspec'ов» — именно так |
| Новая фича/режим с требованиями | OpenSpec: `/opsx:propose` (proposal + design + specs + tasks) → `/opsx:apply` → `/opsx:archive`; остальные: `/opsx:explore`, `/opsx:sync`, `/opsx:update`. Артефакты — по-русски (`openspec/config.yaml`), заголовки и SHALL/MUST — по-английски. Подробно: [../how-opsx-works.md](../how-opsx-works.md) |
| Идея на потом | `game-plans.md` (детальные планы + оценки) или `todo.md` (короткие идеи); выполненное из `game-plans.md` переносят в «Выполнено» с датой и временем |
| Исследование («режим исследования/планирования», «проведи исследование») | **ничего не менять в коде**: изучить, привести проверенные факты, таблицу вариантов и оценку трудозатрат в токенах, рекомендацию; реализовывать только после «да» |

Принципы, выстраданные на реальных откатах:

- **Минимально и по просьбе.** «Добавь тумблер» значит тумблер, а не правка границ
  штатов рядом. Нельзя убирать запрошенное, когда исправляешь соседний баг.
- **Простейшая версия → проверка вживую → усложнение.** Пример: система «всегда
  показывать подписи мелких стран» (коллизии, подгонка размера, приоритеты) была
  спроектирована целиком заранее, содержала баг измерения, который «проверочный»
  скрипт не ловил (он использовал оценочную ширину текста, а не реальную), добавляла
  O(n²) на событие колеса без троттлинга — и в итоге была откачена целиком.
  Перед работой на «горячем» обработчике (`wheel`, `pointermove`) оцени частоту вызова.
- **Проверка не должна разделять допущение с кодом.** Скрипт-проверка, который
  повторяет ту же логику теми же входами, ничего не доказывает.
- **Реальные данные, честные оговорки.** Если пришлось приблизить — написать в ответе
  и в документации (как с Гольфстримом: путь реальный, начало и конец подрезаны).
- **Обратная связь владельца краткая и иногда эмоциональная.** «Ну ты понял» — обобщи
  просьбу на соседние случаи единообразно (пример: «Моря (23)» → счётчики на всех
  вкладках). «Ничего не меняй» — только читать. Скриншот с «видишь баг?» без деталей —
  сначала уточни, что не так.

## Git

- Рабочая ветка — `master`. Есть ещё ветки `ocean-and-seas`, `open-street-map`,
  `optimization`, `re-design`, `release-18.08.2026` (на GitHub есть их копии).
- Remote'ы: `origin` → GitHub `Skycader/geo-puzzle`; `origin-gitlab` → GitLab
  `daniil.ustimencko/geo-puzzle`. На GitLab у `HEAD` ветка `main` — один коммит «Initial commit»,
  общей истории с `master` нет; её не трогаем.
- **Коммитить и пушить только по просьбе** («commit and push» или «cap» — это одно и то же). «Push» =
  в оба remote'а: `git push origin master` и `git push origin-gitlab master`.
- **Страховочная копия (запускает владелец, не ассистент):** `bash scripts/backup_to_obsidian.sh` кладёт zip
  последнего коммита (`GeoPuzzle_<дата>_<время>_<хэш>.zip`, без `.git`) в папку «12. Projects»
  хранилища Obsidian на этой машине (оно синхронизируется по облакам, дискам и телефону —
  копия, не зависящая от аккаунтов GitHub/GitLab). Для того же коммита второй раз не создаётся.
  В архив попадает только закоммиченное (`git archive HEAD`), поэтому запускать после коммита.
  После каждого `cap` ассистент лишь **напоминает** про этот скрипт и сам его не вызывает.
- Коммит: `git add <конкретные файлы>` (не `-A`), заголовок по-английски — что и зачем,
  в конце строка `Co-Authored-By: <модель> <noreply@anthropic.com>`. Не amend,
  не force-push, не `--no-verify`.
- Git на Windows предупреждает «LF will be replaced by CRLF» — это нормально; при
  правке файлов скриптами сохраняй исходные окончания строк файла.
- Если GitLab просит логин / падает Git Credential Manager — см.
  [../instructions.md](../instructions.md) (обновить Git, сбросить сохранённые данные,
  токен или SSH).

## Версия и журнал изменений

Версия — `APP_VERSION` в `js/version.js` (сборки нет, это единственный источник); кнопка с ней в шапке
открывает модалку со вкладкой на каждый выпуск. Схема до 1.0: минорное число растёт за крупный этап
(новый уровень, режим, семейство слоёв), патч — за исправления. Порядок выпуска (по слову «релиз»):
1. поднять `APP_VERSION` и поставить версию **первой** в `RELEASES` (`js/version.js`);
2. написать `changelog/<версия>.md` (Добавлено / Изменено / Исправлено; поддерживаются `#`–`###`, списки,
   `**жирный**`, `` `код` ``, ссылки `https://…`);
3. закоммитить и поставить тег `v<версия>`.
`cap` версию не меняет. Первая запись — `0.9.0` (22.10.2026), нумерация этапов задним числом условная.

**Накопление до релиза.** Следующий выпуск — `1.0.0`; пока владелец не скажет «Выпускаем новый релиз»,
его записи копятся в черновике `changelog/1.0.0.md` (заголовок «не выпущено»). Каждое изменение,
заметное пользователю, добавляется туда в том же коммите, что и сам код (Добавлено / Изменено /
Исправлено; внутренняя кухня вроде рефакторинга и docs — не пишется). Черновика нет в `RELEASES`,
`APP_VERSION` остаётся `0.9.0`, коммиты идут в `master` как обычно. По фразе «Выпускаем новый релиз»:
заголовок файла → «1.0.0 — <дата>», убрать абзац про черновик, `APP_VERSION = '1.0.0'`, `'1.0.0'` первой
в `RELEASES`, закоммитить и поставить тег `v1.0.0`.

## Стиль кода

- Ванильный JS (ES-модули), без зависимостей. Комментарии — английские, объясняют
  **почему** (скрытое ограничение, баг, причина решения), а не что делает код;
  строки интерфейса — русские (+EN в `js/i18n.js`), русский — источник истины там,
  где он уже живёт (данные уровней, `js/modes.js`), в `i18n.js` лежит только
  английская дельта.
- CSS: **никаких скруглений** (везде `border-radius: 0`), неоновая тема, переменные
  `--neon-*`; элементы, цвет которых не должен меняться между схемами (аэропорты,
  течения), красятся фиксированным цветом.
- Полосы прокрутки — одна общая кастомная (раздел `scrollbars` в `style.css`: тёмная рейка, квадратный
  ползунок с градиентом cyan→violet, свечение при наведении, розовый при перетаскивании; цвета на
  `--neon-*-rgb`, поэтому серая схема её перекрашивает). Не задавать `scrollbar-width/-color` на отдельных
  элементах: Chrome тогда игнорирует `::-webkit-scrollbar` (они стоят только в `@supports not selector`
  для Firefox). Свою полосу рисовать не надо — любой `overflow: auto` получает её сам.
- Размеры значков/подписей на карте — в пикселях экрана (пересчёт в
  `_rescaleForZoom`), не в единицах холста.
- Не плодить абстракции и обработку невозможных ошибок; новые слои делать по рецепту
  из [overview-mode.md](overview-mode.md).

## Если история чата потеряна

1. Прочитать [welcome.md](welcome.md), затем нужный файл из оглавления.
2. `git status` — нет ли незакоммиченной работы; `git log --oneline -20` — что делали последним.
3. Активные планы: [../game-plans.md](../game-plans.md), [../todo.md](../todo.md),
   `openspec/changes/` (незакрытое изменение — `state-placement-mode`).
4. Прежде чем «чинить», посмотреть, нет ли уже заметки в `docs/` или в комментариях кода
   рядом — многие решения записаны именно там.
5. Личные заметки ассистента лежат вне репозитория (`~/.claude/projects/…/memory/`) и
   могут быть недоступны; их суть перенесена в этот документ и в
   [architecture.md](architecture.md) («Подводные камни»).
