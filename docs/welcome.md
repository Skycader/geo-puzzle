# GEO PUZZLE — читать первым

> Точка входа для нейросети (или человека) после потери истории чата. Здесь
> то, что нужно знать до первой правки; детали в файлах из оглавления ниже.

## Что это за проект (60 секунд)

**GEO PUZZLE** — браузерная игра-тренажёр по географии на ванильном JS
(ES-модули, без сборщика, без `package.json`). Карта рисуется SVG. Есть три
«уровня» (карты): **США: штаты**, **Моря и океаны**, **Страны мира** — и
~12 режимов: от пазла и викторин до свободного «Обзора» (карта со слоями:
города, места, озёра, шоссе, аэропорты, течения, рельеф).

| Что | Где |
|---|---|
| Автор / роль | Skycader (GitHub), владелец и заказчик; ведёт проект с нейросетью |
| Стек | HTML + CSS + vanilla JS (ES modules), SVG; скрипты сборки данных на Node.js (CommonJS); dev-сервер на Python |
| Язык | интерфейс RU (основной) + EN; документы и общение — по-русски; комментарии в коде в основном английские |
| Данные | `levels/*.js` и `levels/*/*.json` (сгенерированы скриптами из открытых источников) |
| Код игры | `js/` (~35 файлов, ~12 тыс. строк; два крупнейших: `overviewBoard.js` ~3,1 тыс., `game.js` ~2,3 тыс.) |
| Сборка данных | `scripts/` + исходники в `scripts/data/` |
| Разметка и стили | `index.html` (~0,4 тыс. строк), `style.css` (~3,4 тыс. строк) |

Подробнее: [overview.md](overview.md) (что умеет), [architecture.md](architecture.md) (как устроено).

## Быстрый старт

Нужны Python 3 и (для скриптов данных) Node.js ≥ 18. Игра открывается **только
по http** (ES-модули и `fetch` JSON не работают с `file://`).

```bash
python scripts/dev_server.py 5720     # порт по умолчанию 5720
# затем открыть http://localhost:5720/
```

Тот же запуск прописан в `.claude/launch.json` (имя конфигурации `geo-puzzle`).
Сервер многопоточный и отдаёт всё с `Cache-Control: no-store`.

Проверки (автотестов в проекте **нет**):

| Что проверить | Как |
|---|---|
| Синтаксис JS-файла | `node --check js/overviewBoard.js` (работает и для ES-модулей) |
| Что игра запускается | открыть страницу, выбрать уровень и режим, нажать «Играть», смотреть консоль на ошибки |
| Перегенерация данных | `node scripts/build_<имя>.js` (см. [data-pipeline.md](data-pipeline.md)) |
| Спецификации OpenSpec | `openspec validate --specs` |

## Правила работы

Взяты из практики проекта и сохранённых заметок. Нарушать только по прямой
просьбе владельца.

1. **Не коммить и не пушь без просьбы.** Только когда сказано «commit and push»
   (или «cap»). Remote'ов два: `origin` (GitHub) и `origin-gitlab` (GitLab); при
   «push» пушат в **оба**, ветка `master`. Подробнее в [workflow.md](workflow.md).
2. **Сообщение коммита** заканчивается строкой `Co-Authored-By: <модель> <noreply@anthropic.com>`
   (модель — как указано в системной подсказке Claude Code); сообщения
   по-английски, коротко «что и зачем».
3. **Минимальный объём правки.** Делай ровно то, что просили. Не удаляй и не
   переделывай запрошенное, не меняй соседнее поведение. Если сказано «ничего не
   меняй» — только читать. Был реальный инцидент: просили «просто добавь
   тумблер», а были изменены границы штатов — владелец откатывал несколько раз.
4. **Реальные данные вместо приближений.** Не выдумывай «правдоподобные»
   геометрии и числа. Если данных нет — найди источник; если приближение
   неизбежно — прямо напиши об этом (пример: Гольфстрим по данным OSCAR, начало
   и конец подрезаны, это оговорено).
5. **Сначала простейшая версия, проверка вживую, потом усложнение.** Не
   проектируй сложную систему заранее (подробный разбор на примере отката
   «подписей мелких стран» — см. [workflow.md](workflow.md)).
6. **Сгенерированные файлы не правь руками**: `levels/usa*.js`, `levels/world*.js`,
   `levels/countries.js`, `levels/usa/airports-info.json` и т. п. Меняй скрипт или
   его вход и перегенерируй. В шапке каждого такого файла написана команда.
7. **Проверяй глазами.** Правки UI — в браузере, со скриншотом; наведение
   (hover) — настоящим движением мыши, а не синтетическими событиями. Скриншот
   в Browser-панели ненадёжен для анимаций и после `resize_window` — см.
   «Подводные камни» в [architecture.md](architecture.md).
8. **Багрепорт без деталей — сначала спроси, что именно не так**, и только
   потом чини (когда владелец пишет «видишь баг?» со скриншотом).
9. **Крупное — через OpenSpec, быстрое — без.** Новые режимы/фичи с
   требованиями ведём как OpenSpec-изменение (`/opsx:propose` → `/opsx:apply` →
   `/opsx:archive`). Если владелец сказал «без openspec'ов, так быстрее» — делай
   сразу. Справка: [../how-opsx-works.md](../how-opsx-works.md).
10. **`game-plans.md`**: сделанный пункт не удаляют — переносят целиком в раздел
    «Выполнено» с датой и временем. Для `todo.md` это правило не действует.
11. **Стиль CSS: никаких скруглений** (в `style.css` везде `border-radius: 0`).
    Новые элементы делай так же.
12. **Слои «Обзора» независимы.** Каждый слой — отдельный переключатель в меню
    «Слои» + иконка источника данных; не привязывай новый слой к существующему
    тумблеру (так уже исправляли: аэропорты «спрятали» в «Места»).
13. **Не вставляй в документы непроверенные числа.** Если не уверен — пиши
    «~» или «не проверено». Если код расходится с текстом — прав код.

## Состояние проекта

Версии нет (тегов нет; есть ветки `master`, `ocean-and-seas`, `open-street-map`,
`optimization`, `re-design`, `release-18.08.2026`). В `master` ~150 коммитов с

**Сделано недавно (по `git log`, конец сентября — октябрь 2026):**
расширение «Морей и океанов» до ~277 акваторий (Natural Earth 10m, проливы,
заливы); тумблер «Едва заметные границы штатов» в «Назови штат»; счётчики на
вкладках «Обзора»; вкладки **Шоссе** (поиск по номеру, подсветка), **Аэропорты**
(144 шт., настоящие ВПП, самолёт/вертолёт), **Течения** (пилот: Гольфстрим);
иконки источников данных у слоёв; новые города и места (Норфолк, Саффолк,
Арлингтон, Такома-Парк, Пентагон, Аппалачи, Route 66, мост через Пончартрейн,
