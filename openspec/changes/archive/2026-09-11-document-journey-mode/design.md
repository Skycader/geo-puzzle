## Context

См. `proposal.md` — это ретроактивная документация уже существующего,
рабочего кода, а не новая архитектура. Раздел "Decisions" ниже — не выбор
между альтернативами, а карта "требование спеки → где это реализовано в
коде", чтобы при следующей правке идти сразу в нужное место, а не искать
заново.

## Goals / Non-Goals

**Goals:**
- Дать точную карту "требование → реализация" для будущих правок режима.
- Зафиксировать неочевидные инварианты (см. "Decisions"), которые в этой
  сессии приходилось объяснять себе заново по коду несколько раз.

**Non-Goals:**
- Не описывает `js/journeyRoute.js` (подбор пары/цепочки штатов) в
  деталях — это отдельная зона ответственности, вне текущей спеки.
- Не описывает общий движок доски (`zoomPan.js`, `utils.js`) — это общая
  инфраструктура, используемая многими режимами, не специфика Путешествия.

## Decisions

**Карта требование → код:**

| Требование спеки | Реализация |
|---|---|
| Подбор пары по сложности | `js/game.js`'s `_startJourney` → `pickJourneyPair` (`js/journeyRoute.js`) с `min`/`max` из `JOURNEY_DIFFICULTIES` (`js/modes.js`) |
| Свободный порядок называния | `JourneyNameBoard._confirm()` — принятие проверяется через `this.accepted` (Set всех принятых id), не через позицию в `this.chain` |
| Условие принятия догадки | `_confirm()`: `isAdjacent = (matchedPiece.neighbors).some(n => this.accepted.has(n))` |
| Повторное называние | `_confirm()`: ветка `if (this.accepted.has(id))` → `_pulseAlreadyAccepted` |
| Условие победы (связность) | `_isConnected()` — BFS от `startPiece` по `this.accepted`, побеждает при достижении `endPiece.id` |
| Награда только за исходную цепочку | `_confirm()`: `isChainState = this.toGuess.includes(id)` (`toGuess` = `this.chain.slice(1, -1)`) |
| Три режима ответа | `js/game.js`'s `_startJourney`: ветка `puzzle`/`puzzle-blind` → `PuzzleBoard` (с `hintsVisible` для различия обычный/вслепую); иначе → `JourneyNameBoard` |
| Тумблер "Подписывать штаты" | `opts.labelStates` → `JourneyNameBoard._buildStatePiece` (гейт добавления `<text>`-подписи), плюс `hideStart`/`hideEnd` в `_updateProgressText()` и в `js/game.js`'s HUD-строке |
| Тумблер "Показывать штат назначения" | `opts.showDestination` → конструктор `JourneyNameBoard`: конечный штат НЕ добавляется в `this.accepted` при старте, если тумблер выключен — единственный путь попасть в `accepted` тогда тот же, что и у любого другого штата (через `_confirm()`'s обычную проверку смежности) |
| Подсказка не раскрывает конечный штат | `_nearestUnguessedChainState()` — ищет только среди `this.toGuess` (`chain.slice(1, -1)`), конечный штат туда никогда не входит |

## Risks / Trade-offs

- **Спека может разойтись с кодом со временем** — если код изменится, а
  эту спеку не обновят через `/opsx:sync`/`/opsx:apply`, она станет
  источником неверной информации. Смягчение: перед тем как ДЕЙСТВОВАТЬ по
  спеке (не просто читать для ориентира), свериться с реальным кодом —
  то же правило, что уже применяется к файлам памяти агента в этом
  проекте.
- Таблица выше называет конкретные функции/поля — при рефакторинге имена
  могут устареть раньше, чем текст самих Requirements/Scenarios (которые
  описывают только наблюдаемое поведение, не реализацию).
